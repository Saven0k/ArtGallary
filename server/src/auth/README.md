# Подтверждение действий через почту

Смена пароля, смена email и удаление собственного аккаунта подтверждаются шестизначным кодом из письма. Аккаунт определяется сервером по авторизованной сессии. Вводить текущий email и текущий пароль в настройках не нужно.

- **Пароль:** `POST /auth/password-change/request-code` отправляет код на почту аккаунта; `POST /auth/password-change/verify-code` принимает `{ "code": "123456" }` и выдаёт одноразовое подтверждение `resetToken`. Затем `POST /auth/change-password` принимает `{ "resetToken": "...", "newPassword": "..." }`. После смены пароля все сессии завершаются, нужно войти заново.
- **Email:** `POST /auth/email-change/request-code` принимает `{ "newEmail": "new@example.com" }`. Код отправляется **на текущую почту**, а в письме указан новый адрес. `POST /auth/email-change/confirm` принимает `{ "newEmail": "new@example.com", "code": "123456" }`. Код привязан к пользователю, текущему и новому адресу; пароль дополнительно не запрашивается.
- **Удаление:** `POST /auth/account/delete/request-code` отправляет код на почту аккаунта. `POST /auth/account/delete/verify-code` принимает `{ "code": "123456" }` и выдаёт одноразовый `deletionToken`. Фронт сразу передаёт его в `X-Account-Deletion-Token` при удалении своего профиля через существующий API пользователей или авторов. Предупреждение о последствиях показывается до отправки кода; финальная кнопка удаления нажимается явно.

Восстановление забытого пароля на странице входа сохраняет маршруты `/auth/password-reset/...`. Контракт `/auth/change-password` теперь требует подтверждение кода вместо текущего пароля: фронт и бэк нужно обновлять вместе. Профиль нельзя использовать для обхода подтверждения собственных email и пароля, включая аккаунты модератора и администратора. Управление чужими профилями из админки сохраняется.

Код действует 15 минут, допускается пять неверных попыток. Повторную отправку можно запросить через минуту. После проверки кода пароля или удаления выдаётся подтверждение на пять минут, которое нельзя использовать повторно. Пароль и email сохраняются с потреблением подтверждения в одной транзакции. При смене email незавершённые подтверждения пароля и удаления для прежней почты аннулируются. Коды хранятся в виде хешей и не выводятся в логи.

Письма и интерфейс поддерживают `lang=ru`, `lang=en`, `lang=zh`. На фронте этот параметр добавляется общим клиентом API. Письма используют существующий HTML-шаблон галереи и содержат код, назначение действия и срок действия.

## Настройка отправки

Нужны существующие переменные окружения `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM` и `FRONTEND_URL`. Для Gmail: `SMTP_HOST=smtp.gmail.com`, `SMTP_PORT=587`, в `SMTP_USER` — адрес отправителя, в `SMTP_PASS` — пароль приложения. Заполнять их нужно в локальном игнорируемом env-файле либо в настройках сервера/Coolify; секреты в Git не добавлять.

Без настройки SMTP код не считается отправленным: сервер возвращает 503, в модалке показывается ошибка. Недоставленный код удаляется, чтобы можно было повторить отправку после исправления настроек. При ошибке SMTP в ответ не попадают технические детали с учётными данными. Схема существующих таблиц не меняется, новая миграция не требуется.

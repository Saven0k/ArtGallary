# Промокоды

## Как пользоваться

1. Войти на сайт под **администратором** и открыть **Админка → Промокоды** (`/admin?section=promoCodes`).
2. Указать код и скидку от **1 до 100%**. Код состоит из **3–32 латинских букв, цифр, дефисов или подчёркиваний**. Регистр не имеет значения: `gallery10` сохраняется как `GALLERY10`.
3. При необходимости указать дату и время окончания. Поле использует часовой пояс компьютера администратора; API и БД сохраняют абсолютный момент времени. Без даты код действует, пока его не отключат.
4. Нажать **Создать промокод**. В списке можно включать и отключать коды. У уже истёкшего кода включение не продлевает срок.
5. Покупатель вводит код в корзине и нажимает **Применить**. После проверки сервером показываются код, процент и сумма скидки. При изменении количества скидка пересчитывается.

Интерфейс доступен на русском, английском и китайском. Управление закрыто для модераторов, авторов и обычных пользователей. Проверить код в своей корзине могут все авторизованные пользователи.

Код и процент после создания не редактируются: для другой акции создайте новый код, старый отключите. Удаления нет, чтобы сохранять понятную историю акций. Оформленные заказы хранят собственный снимок цены и скидки, отключение промокода их не меняет.

## Правила расчёта

- Одна процентная скидка на стоимость работ в заказе; доставка в расчёт не входит.
- Действует для RUB, USD и CNY. Работы с разными исходными валютами по-прежнему оформляются отдельно.
- Скидка округляется до двух знаков: `100,55 × 10% = 10,06`, итог `90,49`. Конвертация для показа не меняет валюту заказа.
- В момент оформления сервер заново читает корзину, проверяет доступность работ, цены, количество и промокод. Переданные клиентом процент, цена или итог не принимаются.
- Если код отключили или он истёк после применения, заказ не создаётся, корзина сохраняется, код сбрасывается с сообщением об ошибке.
- Строка промокода блокируется в транзакции оформления. Параллельное отключение ждёт окончания уже начавшегося оформления; если отключение прошло первым, новый заказ скидку не получит.
- Пока используются существующие правила оформления проекта. Интеграция с платёжным провайдером этой функцией не добавляется.

Лимитов числа применений, персональных кодов и комбинирования акций нет.

## Обновление сервера

Изменились **и фронтенд, и API**, добавилась таблица `promo_codes`. Обновляйте их вместе.

### Coolify

В конфигурации `compose.coolify.yaml` стартовый скрипт API автоматически применяет SQL из `deploy/sql` перед запуском сервера. В этой версии добавлен файл `20261022-promo-codes.sql`. Проверьте успешное завершение миграции в логах API; постоянный режим `DB_SYNC=alter` не нужен.

Миграция переносит прежние `SALE10` (10%), `SALE15` (15%) и `ART20` (20%) в БД. В дальнейшем ими управляет администратор. Повторный запуск SQL не меняет уже существующие коды и не включает отключённые.

### Обычный Docker и запуск без Docker

Сделайте резервную копию рабочей БД. Затем примените SQL к той базе, которую использует API, например из корня репозитория:

```sh
psql -h 127.0.0.1 -p 5432 -U postgres -d gallery -v ON_ERROR_STOP=1 -f deploy/sql/20261022-promo-codes.sql
```

Замените адрес, порт, пользователя и имя базы своими значениями. Пароль вводите в запросе `psql`; не записывайте его в команду или Git. Затем пересоберите и перезапустите API и фронтенд. Новые переменные окружения не требуются. В разработке `DB_SYNC=create` создаёт таблицу из модели; SQL дополнительно устанавливает ограничения и переносит старые коды.

В `deploy/docker-compose.yml` автоматического запуска SQL нет. Примените тот же файл к контейнеру БД перед перезапуском API. Пример для Bash из корня проекта (имя пользователя и базы замените своими):

```sh
docker compose -f deploy/docker-compose.yml exec -T db psql -U postgres -d gallery -v ON_ERROR_STOP=1 < deploy/sql/20261022-promo-codes.sql
```

Для PowerShell передайте содержимое через конвейер:

```powershell
Get-Content -Raw deploy/sql/20261022-promo-codes.sql | docker compose -f deploy/docker-compose.yml exec -T db psql -U postgres -d gallery -v ON_ERROR_STOP=1
```

## API

Пути указаны относительно API. В production перед ними обычно стоит `/api`. Используются текущая cookie-сессия и общая передача `lang=ru|en|zh`.

| Метод | Путь | Доступ | Назначение |
|---|---|---|---|
| GET | `/promo-codes?page=1&limit=20` | admin | Список; `page ≥ 1`, `limit` от 1 до 100 |
| POST | `/promo-codes` | admin | Создание |
| PATCH | `/promo-codes/:id` | admin | Только переключение `active` |
| POST | `/promo-codes/validate` | user, author, moderator, admin | Проверка доступности кода |
| POST | `/cart-history/checkout` | Авторизованный покупатель | Повторная проверка и оформление |

Создание:

```json
{ "code": "WELCOME2026", "percent": 12, "expiresAt": "2027-01-01T00:00:00.000Z" }
```

`expiresAt` можно не передавать или указать `null`. Управление статусом: `{ "active": false }`.

Проверка: `{ "code": "welcome2026" }`. Успешный ответ:

```json
{ "code": "WELCOME2026", "percent": 12, "expiresAt": "2027-01-01T00:00:00.000Z" }
```

Оформление:

```json
{ "items": [{ "artId": 7, "quantity": 2 }], "promoCode": "WELCOME2026" }
```

Основные ошибки: `400 PROMO_CODE_INVALID` — неизвестный, отключённый или истёкший код; `400 PROMO_EXPIRY_INVALID` — дата создания акции в прошлом; `409 PROMO_CODE_EXISTS` — код уже существует. Ошибки доступа: 401/403. Фронтенд показывает переведённое сообщение и отличает сбой соединения от недействительного кода.

Стабильный идентификатор ошибки возвращается в поле `code`; поле `message` может быть переведено. Клиент проверяет `code`, поэтому смена языка и серверный перевод не влияют на сброс отключённого промокода или распознавание дубликата.

## Проверки

Из `frontend/`:

```sh
node --test src/__tests__/api.test.cjs src/__tests__/profile-commerce.test.cjs src/__tests__/art-pricing.test.cjs src/__tests__/localization.test.cjs
npm run build
npm run lint
```

Из `server/`:

```sh
npm test -- --runInBand --runTestsByPath src/promo-codes/promo-codes.service.spec.ts src/promo-codes/promo-codes.controller.spec.ts src/cart-history/cart-history.service.spec.ts src/database/migrations.spec.ts
npm run build
npm run lint:check
```

Отдельный тест `promo-codes.integration.spec.ts` проверяет настоящую PostgreSQL: миграцию, ограничения, одновременное создание одного кода и блокировку при отключении. Он запускается только с `PROMO_TEST_DATABASE_URL`, указывающим на **отдельную локальную тестовую БД** `gallery_promo_test` на порту от 20000. Тест очищает таблицу промокодов в этой тестовой БД. Не используйте рабочую базу.

```sh
PROMO_TEST_DATABASE_URL=postgres://postgres@127.0.0.1:55436/gallery_promo_test npm test -- --runInBand --runTestsByPath src/promo-codes/promo-codes.integration.spec.ts
```

PowerShell: сначала `$env:PROMO_TEST_DATABASE_URL='postgres://postgres@127.0.0.1:55436/gallery_promo_test'`, затем команда `npm test` из примера. Без этой переменной PostgreSQL-тест пропускается.

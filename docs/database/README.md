# GalleryTema — актуальная диаграмма БД

Откройте [GalleryTema-current.drawio](GalleryTema-current.drawio) в draw.io / diagrams.net через **Файл → Открыть с → Устройство**.
Все таблицы, строки полей и соединения редактируются. [Обзор в SVG](GalleryTema-overview.svg) можно масштабировать,
[обзор в PNG](GalleryTema-overview.png) подходит для быстрого просмотра.

## Страницы

1. **Обзор всей БД** — все таблицы и ключи.
2. **Аккаунты** — пользователи, профили авторов, роли, профессии, сессии и коды подтверждения.
3. **Каталог** — работы, виды искусства, жанры, стили, теги, события и география.
4. **Активность и заказы** — просмотры, лайки, подписчики, аналитика, корзины и история заказов.
5. **Тарифы и уведомления** — подписки авторов, история оплаты, email и browser push.
6. **Telegram и сервис** — привязки, задачи модерации, состояние бота, кеш переводов и SQL-миграции.

## Источник и границы

Снимок исходников `2814251`, 20 октября 2026. Использованы 34 модели из
[server/src/database/models.ts](../../server/src/database/models.ts), зарегистрированные в Sequelize без подключения к БД;
SQL из [deploy/sql/](../../deploy/sql/) и журнал из [server/src/database/migrations.ts](../../server/src/database/migrations.ts).
Итого: **35 таблиц, 277 полей**. Журнал `_schema_migrations` добавлен как служебная таблица SQL.
Фактическая схема опубликованного сервера не выгружалась, поэтому её совпадение со снимком не подтверждено.
Исходные пользовательские drawio-файлы, код приложения, данные и миграции не изменены.

После этого снимка добавлена таблица `promo_codes`: код акции, процент, активность, срок действия и даты создания/обновления. Она описана в [документации промокодов](../PROMO-CODES.md) и миграции `20261022-promo-codes.sql`; в изображениях диаграммы от 20 октября её ещё нет.

Сплошные связи — **39 FK, формируемых текущими моделями ORM**. Пунктир REF / JSON обозначает ссылки
приложения без ограничения SQL. `SQL*` — ссылки на users из notification_settings и push_subscriptions,
описанные в CREATE TABLE IF NOT EXISTS SQL-миграции: если таблицы ранее созданы через ORM,
эта миграция не добавляет к ним отсутствующие внешние ключи. Наличие этих двух FK зависит от истории БД.
На обязательном конце FK показано 1, на nullable-конце — 0..1; со стороны дочерних записей — 0..N,
либо 0..1 при уникальном FK. Для пунктирных связей ограничения БД из этих обозначений не следуют.

PK — первичный ключ; FK — внешний; UQ — уникальное поле / сочетание. ● — NOT NULL, ○ — NULL.
INT = INTEGER, TIMESTAMPTZ = TIMESTAMP WITH TIME ZONE. ENUM-значения подписаны на детальных страницах.
Автоматические createdAt / updatedAt сохранены даже там, где модель также объявляет created_at / updated_at.

## Что изменилось относительно переданных диаграмм

- Актуальные имена: author_profiles, arts, genres, art_types, events и др.
- В author_profiles первичный ключ user_id, который ссылается на users.id; отдельного id нет.
- arts.author_id ссылается на author_profiles.user_id. Вид искусства определяется через genre_id → genres.art_type_id.
- art_tags имеет составной PK (art_id, tag_id). UQ подписки: subscriptions.author_id.
- Корзина и история заказов хранят art_ids в JSONB; pricing — снимок состава и стоимости заказа.
- Нет прежних artist / exhibition / comment и таблиц участия в выставках: в текущем реестре моделей их нет.
- Добавлены подписки, уведомления, push, Telegram, кеш перевода и служебные таблицы.

## Особенности текущего кода, отражённые без изменения

- Поля email_change_codes.user_id, account_deletion_codes.user_id, moderators.assigned_by
  и telegram_accounts.pending_delivery_id не формируют внешний ключ в текущей ORM-регистрации.
- telegram_moderation_deliveries.entity_id — полиморфная ссылка: kind=art либо kind=author, без SQL FK.
- JSON-поля moderate / specifications / metadata не разворачиваются в несуществующие таблицы.
- Содержимое notifications.target_id / metadata зависит от типа уведомления; общего SQL FK нет.
- content_translations кешируется по ключу и не имеет прямых FK к исходным сущностям.
- ArtLike.static indexes не попадает в options.indexes текущей регистрации ORM; предполагаемый
  UQ (art_id, user_id) не показан как гарантированный индекс БД.

# Задание для Codex на новом домашнем ПК

## Цель и принятые решения

Разверни этот проект на данном домашнем ПК для постоянной работы. Нужен работающий production-сайт с новой пустой БД. Старые пользователи, арты, события, картинки и БД не переносятся: владелец заполнит сайт заново. Не удаляй имеющиеся на новом ПК базы и чужие данные ради чистого запуска.

Репозиторий: https://github.com/Saven0k/ArtGallary.git, ветка `master`. Пример размещения: `C:\Projects\ArtGallery`. Сначала проверь фактическую ОС, оборудование, путь проекта, установленные инструменты и занятые порты. Инструкция рассчитана на Windows 11 x64. Если ОС другая, сообщи об этом и адаптируй план до установки Windows-инструментов.

Прочитай актуальные исходники конфигов и инструкции:

- `deploy/README.md` — установка, новая БД, домашний сервер и сеть;
- `TRANSLATION.md` — бесплатный перевод RU/EN/ZH;
- `TELEGRAM.md` — модерация через Telegram и бесплатный прокси;
- `deploy/NOTIFICATIONS.md` — SMTP и браузерные push;
- `deploy/windows/prepare.cjs`, `start.ps1`, `update.ps1`;
- `deploy/ecosystem.config.cjs`, `deploy/Caddyfile`.

Используй текущие файлы репозитория как источник фактических команд. Ссылка на старый чат не требуется для выполнения задания. В этом файле нет настоящих паролей и токенов.

## Что нужно сделать

Выполни установку и запуск, а не ограничивайся планом. Используй имеющиеся скрипты, исправляй выявленные ошибки настройки в пределах запуска. Бизнес-логику приложения менять не требуется. Не запускай dev-сервер вместо production. Если шаг требует прав администратора, перезагрузки, доступа к роутеру или отсутствующего секрета, объясни конкретную причину и продолжай независимые шаги.

Запиши фактический результат каждого этапа. Не называй сервис проверенным только потому, что конфиг существует или команда была запущена.

## 1. Инструменты

Нужны Git, Node.js 22.x, npm, PostgreSQL 17 с Command Line Tools, PM2, Caddy Windows amd64. Для перевода — Docker Desktop с WSL 2 и Linux containers. Предпочтителен CPU-вариант переводчика; ранее проект ориентировался на 16 ГБ RAM и GTX 1050 Ti. Проверь ресурсы этого ПК отдельно. Отдельный Ollama в Windows не нужен.

Официальные ссылки установки находятся в `deploy/README.md`. Скачивай установщики только из официальных источников. При необходимости установки WSL проверь виртуализацию в BIOS/UEFI; установка может потребовать перезагрузки. [Команды WSL](https://learn.microsoft.com/en-us/windows/wsl/basic-commands), [требования Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/).

Проверь:

```powershell
git --version
node --version
npm.cmd --version
```

При отсутствии PM2:

```powershell
npm.cmd install -g pm2
pm2.cmd --version
```

Размести Caddy в `deploy/bin/caddy.exe` либо проверь его доступность в PATH. У PostgreSQL должна работать Windows-служба с автоматическим запуском. Используй одного Windows-пользователя и одинаковый уровень прав при управлении PM2.

Если проект ещё не скачан:

```powershell
New-Item -ItemType Directory -Force C:\Projects
Set-Location C:\Projects
git clone https://github.com/Saven0k/ArtGallary.git ArtGallery
Set-Location C:\Projects\ArtGallery
```

Если checkout уже существует, сначала проверь `git status` и текущую ветку. Не перезаписывай пользовательские изменения и не клонируй проект поверх существующего каталога.

## 2. Сборка и приватный конфиг

Из корня проекта, останавливаясь и исправляя ошибку после каждой неуспешной команды:

```powershell
Set-Location server
npm.cmd ci
npm.cmd run build
Set-Location ../frontend
Set-Content -LiteralPath .env.production.local -Value 'VITE_API_URL=/api' -Encoding ascii
npm.cmd ci
npm.cmd run build
Set-Location ..
node deploy/windows/prepare.cjs
```

Перед изменением уже существующего `.env.production.local` проверь его содержимое и сохрани другие нужные настройки. VITE_API_URL должен быть `/api` для production. Переменная попадает в бандл при сборке.

`prepare.cjs` требует установленных зависимостей `server`. Создаёт приватный `server/.production.env`, JWT- и VAPID-ключи и папку загрузок. Уже существующий `.production.env` не перезаписывает. Сохрани его текущие секреты и проверь фактические значения, если файл уже есть.

Настрой `server/.production.env` для локальной проверки. Это фрагмент, остальные сгенерированные параметры сохраняются:

```dotenv
POSTGRES_HOST='127.0.0.1'
POSTGRES_PORT='5432'
POSTGRES_USER='postgres'
POSTGRES_PASSWORD='заполнить-локально'
POSTGRES_DB='gallery'
PORT='5000'
HTTP_HOST='127.0.0.1'
TRUST_PROXY='true'
BASE_URL='/api'
STATIC_DIR='../data/uploads'
FRONTEND_URL='http://localhost'
CORS_ORIGINS='http://localhost'
COOKIE_SECURE='false'
TRANSLATION_ENABLED='false'
TELEGRAM_BOT_ENABLED='false'
```

Задай email первого администратора и его пароль в ADMIN_EMAIL/ADMIN_PASSWORD. Можно сохранить сильный пароль, сгенерированный `prepare.cjs`; владельцу укажи место хранения. Не выводи пароли, JWT/VAPID-секреты и токены в ответы, логи или URL. Не добавляй приватные env в Git. В production `dev.env` не загружается, а переменные окружения процесса имеют приоритет над файлами. Не оставляй устаревший DB_SYNC или подключение к другой БД в окружении команд.

На предыдущем ПК токен бота хранился только в игнорируемых env и проверялся через getMe. Для нового ПК владелец должен отдельно заполнить TELEGRAM_BOT_TOKEN. Не извлекай токены из публичных ссылок или старых сообщений. Токен, попавший в общий чат, следует перевыпустить через BotFather до дальнейшего использования.

## 3. Новая БД и первая инициализация

Создай новую пустую БД через PostgreSQL. Проверь фактический путь утилит. Пример:

```powershell
& 'C:\Program Files\PostgreSQL\17\bin\createdb.exe' -h 127.0.0.1 -p 5432 -U postgres gallery
```

Если `gallery` уже есть, не удаляй и не очищай её автоматически. Установи, относится ли она к этой установке; иначе создай отдельную новую БД и укажи её в POSTGRES_DB. Если пароль PostgreSQL неизвестен, попроси владельца внести его локально в конфиг, не присылать в чат. Не сбрасывай пароль существующего PostgreSQL без отдельного согласования.

Временно поставь в `.production.env` `DB_SYNC='create'`. Из папки `server` запусти:

```powershell
npm.cmd run start:prod
```

Дождись успешного запуска и проверь, что таблицы созданы и администратор появился. В коде ошибка создания администратора может только попасть в лог: одного сообщения о запуске недостаточно. Проверь возможность входа или наличие нужного пользователя с ролью admin, не раскрывая его пароль.

Корректно останови только этот временный API, затем верни в файле `DB_SYNC='false'`. Не оставляй `alter` для постоянного production-запуска.

Для промокодов примените из корня проекта `deploy/sql/20261022-promo-codes.sql` к этой БД: файл устанавливает ограничения и переносит прежние коды. Команда `psql`, порядок обновления и вариант для Docker приведены в [docs/PROMO-CODES.md](../docs/PROMO-CODES.md). На существующей БД этот шаг также нужен до запуска новой версии API.

Из папки `server`:

```powershell
$env:NODE_ENV = 'production'
npm.cmd run seed:geonames:prod
npm.cmd run translations:migrate
npm.cmd run telegram:migrate
Set-Location ..
```

GeoNames скачивает крупные архивы и может выполняться долго. Повторная загрузка использует временный кеш; не запускай несколько сидеров одновременно. Проверь наличие стран и городов. Базовые стили, жанры и виды искусства заполняются при старте; профессии проверь отдельно в админке. При частично завершённой установке сначала проверь фактическое состояние, не создавай данные повторно вслепую.

SQL из `deploy/sql` нужен для обновления старой схемы, а не вместо создания основных таблиц новой БД. Для чистого запуска используй актуальные модели с DB_SYNC=create и отдельные CLI-миграции. Проверяй ошибки команд, не продолжай после неуспешной инициализации.

## 4. Production-сайт

Из корня:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File deploy/windows/start.ps1
pm2.cmd status
curl.exe http://localhost/api/health
```

Ожидаются `gallery-api` и `gallery-web` со статусом online, HTTP 200 от health, доступный `http://localhost`. Caddy отдаёт `frontend/dist` и снимает префикс `/api` перед отправкой в Nest на 127.0.0.1:5000. Отдельный Vite на 5173 для production не нужен.

Health проверяет ответ API, но не выполняет отдельный SQL-запрос. Проверь БД, вход администратором, открытие каталога, загрузку и отображение изображения, API-ошибки и логи. Для тестового контента используй выделенную запись и сообщи о ней владельцу. Не меняй существующие пароли ради проверки входа.

Если PM2 получает `connect EPERM` для rpc.sock, проверь пользователя и права. `start.ps1 -Foreground` допустим для диагностики, но не считается выполненным постоянным запуском: нужен открытый терминал и нет автоперезапуска. Не останавливай посторонние процессы на занятых портах без выяснения их назначения.

## 5. Перевод RU/EN/ZH

Запусти Docker Desktop и проверь Client/Server через `docker version`. Из корня:

```powershell
docker compose -f deploy/translation.compose.yml up -d
docker compose -f deploy/translation.compose.yml exec -T translator ollama pull translategemma:4b
docker compose -f deploy/translation.compose.yml exec -T translator ollama list
```

В `.production.env` включи:

```dotenv
TRANSLATION_ENABLED='true'
TRANSLATION_URL='http://127.0.0.1:11434'
TRANSLATION_MODEL='translategemma:4b'
```

Из папки `server`:

```powershell
$env:NODE_ENV = 'production'
npm.cmd run translations:warm
Set-Location ..
powershell.exe -NoProfile -ExecutionPolicy Bypass -File deploy/windows/start.ps1
```

Проверь переключение языка и ответы API, а не только наличие модели в списке. Ошибки и ненулевой `unavailable` при прогреве разбери по `TRANSLATION.md`. Новые тексты переводятся и кешируются после добавления контента. Исходные значения не должны переписываться переводами.

## 6. Email, push и Telegram

Используй инструкции `deploy/NOTIFICATIONS.md` и `TELEGRAM.md`. SMTP_USER/PASS/FROM и новый токен Telegram владелец заполняет в локальном `.production.env`. Не выдумывай секреты и не считай отсутствующий канал рабочим.

После настройки SMTP перезапусти API и проверь письмо на адрес владельца. Для push сохрани сгенерированную пару VAPID, задай VAPID_SUBJECT и проверь включение и тестовое уведомление на localhost или HTTPS. HTTP по LAN-IP для push не подходит.

Для Telegram сначала проверь getMe через существующий клиент бэкенда с безопасной обработкой ошибок. При блокировке настрой бесплатный локальный HTTP-прокси по `TELEGRAM.md`; фактический порт может отличаться от 8080. Прокси применяется только к Telegram. Одному токену соответствует один запущенный бэкенд. Владелец должен привязать Telegram через `/profile?section=settings` под администратором/модератором и нажать Start. Проверь карточку и решение на тестовой записи после привязки владельца.

Оплата пока не подключена по решению владельца. Настройка YooKassa в эту задачу не входит.

## 7. Домашняя сеть и внешний доступ

Определи LAN-IP, закрепи адрес в DHCP роутера. Открытие веб-портов Windows, из корня в PowerShell с правами администратора:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File deploy/windows/firewall.ps1
```

Нужны только пробросы TCP 80 → LAN-IP ПК:80 и TCP 443 → LAN-IP ПК:443. PostgreSQL 5432, API 5000, Vite 5173, Ollama 11434 и прокси Telegram наружу не публикуются. Бот использует исходящий long polling и отдельного входящего порта не требует.

Проверь наличие публичного IPv4. CGNAT не устраняется пробросом или DDNS. Для HTTPS нужен доступный домен/DDNS с DNS на внешний адрес и доступные входящие порты. В `.production.env` задай реальные FRONTEND_URL/CORS_ORIGINS с https и COOKIE_SECURE=true, затем повтори `start.ps1`.

Не придумывай домен, WAN-IP или факт настройки роутера. Если они пока неизвестны, закончи локальный запуск, укажи точные оставшиеся действия и не называй внешний доступ проверенным. Проверка снаружи выполняется с другого подключения, например мобильного интернета.

## 8. Постоянная работа

Настрой запуск PostgreSQL своей службой, сайта — через существующий start.ps1 и PM2. Создай задачу Планировщика «При входе в систему» для того же Windows-пользователя и с тем же уровнем прав, что запускал PM2. Укажи фактический абсолютный путь к start.ps1, рабочую папку проекта и отсутствие параллельных экземпляров задачи.

В Docker Desktop включи автозапуск при входе. У контейнера уже есть `restart: unless-stopped`. Если нужен прокси Telegram, проверь и его автозапуск. Отключи сон ПК при питании от сети с учётом согласованных настроек владельца; экран можно блокировать через Win+L.

Текущая схема требует входа пользователя после перезагрузки. Не обещай работу до входа в Windows: службы для всех компонентов здесь не подготовлены. Для этого нужна отдельная настройка; [официальные варианты службы Caddy](https://caddyserver.com/docs/running). Реальную перезагрузку согласуй с владельцем и сохрани состояние работы перед ней.

## Результат, который нужно передать владельцу

Укажи фактический URL сайта, путь проекта и приватного конфига, версии установленных программ, имена процессов PM2, состояние Docker/переводчика и параметры новой БД без пароля. Дай точные команды запуска, остановки, просмотра логов и обновления для этой установки.

Перечисли выполненные проверки: вход администратора, изображение, API, география, три языка, email/push/Telegram по отдельности, LAN, внешний HTTPS, автозапуск. Чётко отдели успешные проверки от того, что ждёт секрета, ручного действия или перезагрузки. Не публикуй секреты в итоговом отчёте.

Необходимые внешние действия не должны мешать закончить независимую локальную настройку. Приложение и существующие данные на исходном ПК в этом задании не изменяются.

Настройка уведомлений

Для разработки заполните server/dev.env: SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASS и при необходимости SMTP_FROM. Для Gmail нужен пароль приложения. dev.env исключён из Git и загружается только вне production. Шаблон находится в server/dev.env.example.

FRONTEND_URL должен содержать публичный адрес фронтенда. Письма ведут на этот адрес.

Локальные VAPID-ключи уже созданы. Для нового окружения выполните в server команду npm run push:keys и сохраните publicKey/privateKey в VAPID_PUBLIC_KEY/VAPID_PRIVATE_KEY. VAPID_SUBJECT — mailto:ваш-email или HTTPS-адрес для связи. Храните пару ключей постоянно: её смена требует переподписать браузеры. В production используйте .production.env или переменные окружения процесса.

Примените deploy/sql/20261008-notification-delivery.sql перед запуском обновлённого сервера. DB_SYNC=false предотвращает автоматическое изменение схемы. Старые уведомления не рассылаются.

Push работает на localhost и по HTTPS. Пользователь включает каналы в /settings; разрешение браузера запрашивается только при включении. Настройки и язык сохраняются в аккаунте. Кнопка проверки отправляет уведомление только текущему пользователю, не чаще одного раза в минуту.

Новые подписчики, лайки и новые опубликованные работы создают задания на отправку. Доставка выполняется в фоне с тремя попытками; успешный канал повторно не отправляется. Просроченные подписки браузеров удаляются, выход из аккаунта отключает текущий браузер. Массовой рассылки нет.

Для проверки заполните SMTP, перезапустите сервер, войдите в аккаунт, включите нужный канал и нажмите «Проверить». Внешний вид системного push определяется браузером и ОС; сайт задаёт заголовок, текст, значок и ссылку.

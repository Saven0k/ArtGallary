# Telegram-бот для модерации

Бот работает внутри существующего Nest-бэкенда, использует его PostgreSQL и те же методы модерации, что сайт. Администраторы и модераторы получают карточки авторов и работ, принимают или отклоняют их с комментарием. Отдельный сервер, база и платные API не нужны.

## 1. Создать бота

1. Открой [официального BotFather](https://t.me/BotFather) в Telegram.
2. Отправь `/newbot`, укажи название и свободный username, заканчивающийся на `bot`, например `YourGalleryModerationBot`.
3. Сохрани выданный токен в приватный env бэкенда. Токен позволяет управлять ботом: не присылай его в чат, не помещай в Git и не вводи в публичные сервисы.
4. При желании через `/setcommands` укажи:

```text
queue - Очередь модерации
cancel - Отменить ввод комментария
```

Создание и управление ботами описаны в [документации Telegram](https://core.telegram.org/bots/features#botfather). Публичный username сам по себе не даёт доступ к модерации: нужна привязка через авторизованный аккаунт сайта.

## 2. Подготовить бэкенд

Для разработки заполни `server/dev.env`, для домашнего production — `server/.production.env`. Поля уже есть в `server/dev.env.example` и `server/.env.example`:

```dotenv
TELEGRAM_BOT_ENABLED='true'
TELEGRAM_BOT_TOKEN='токен-из-BotFather'
TELEGRAM_PROXY_URL=''
```

Пустой `TELEGRAM_PROXY_URL` означает прямое подключение. Если Telegram недоступен, используй бесплатный вариант из раздела 5. `FRONTEND_URL` должен содержать адрес сайта, который открывается с телефона: он нужен для ссылки на полную карточку. При локальной разработке можно оставить `http://localhost:5173`, но с другого устройства эта ссылка не откроется.

Из корня проекта установи зависимости и создай таблицы:

```powershell
Set-Location server
npm ci
npm run build
$env:NODE_ENV = 'development'
npm run telegram:migrate
npm run start:dev
```

В другом окне запусти фронт:

```powershell
Set-Location frontend
npm ci
npm run dev
```

Для production вместо `development` перед миграцией укажи:

```powershell
$env:NODE_ENV = 'production'
npm run telegram:migrate
```

После этого запускай сайт через `deploy/windows/start.ps1` по [инструкции домашнего сервера](deploy/README.md). Для существующей БД оставь `DB_SYNC='false'`. Миграция создаёт только три новые таблицы и индексы: `telegram_accounts`, `telegram_moderation_deliveries`, `telegram_bot_state`; записи пользователей, авторов и работ она не переписывает. Повторный запуск безопасен. В совершенно пустой БД сначала создай основные таблицы сайта по инструкции домашнего сервера: таблица `users` должна существовать до миграции Telegram.

С выключенным `TELEGRAM_BOT_ENABLED` или пустым токеном бот не обращается к Telegram. Настройки подключения и переводов сохраняются при подготовке production-конфига через `deploy/windows/prepare.cjs`; уже существующий `.production.env` этот скрипт не перезаписывает.

## 3. Привязать администратора и модераторов

1. Войди на сайте под администратором или модератором.
2. Открой `/profile?section=settings`, блок «Модерация в Telegram».
3. Нажми «Подключить Telegram», затем открой выданную ссылку и нажми **Start** в Telegram.
4. Вернись на сайт и нажми «Проверить привязку». Появится «Telegram подключён».

Каждый модератор привязывает свой аккаунт самостоятельно. Ссылка одноразовая, действует 10 минут; в БД хранится только её хеш. Не пересылай ссылку другим людям. Один Telegram привязывается к одному аккаунту сайта. Кнопка «Отключить» удаляет привязку и состояние этого модератора, не меняя решения по авторам и работам.

Бот отвечает только в личном чате. Для каждого действия и отправки уведомлений проверяется актуальная роль и состояние пользователя в БД. После удаления аккаунта или снятия роли доступ к модерации прекращается. Для будущих пользовательских функций можно использовать эти же привязки и таблицу пользователей; текущая версия предоставляет доступ только сотрудникам.

## 4. Как работает модерация

Раз в 10 секунд бэкенд проверяет непросмотренных авторов и работы. При подключении придут и ранее накопленные записи. Уже принятые и отклонённые записи в эту очередь не попадают; после исправлений автора новая версия может прийти снова.

В карточке есть название или имя, описание, ссылка на сайт и кнопки **«Принять» / «Отказать»**. Изображение загружается в Telegram из локальной папки загрузок, если оно доступно и не превышает 10 МБ. При неподдерживаемом изображении отправляется текстовая карточка. Длинное описание сокращается; полную запись проверяй на сайте.

После нажатия кнопки бот предлагает отправить следующим сообщением комментарий до 2000 символов или нажать **«Без комментария»**. Решение сохраняется только после этого шага. **«Отмена»** и `/cancel` отменяют ввод. Запрос комментария действует 10 минут. Если выбран другой автор или арт, обычное сообщение относится к последнему запросу комментария; для точного ответа используй Reply на сообщение бота.

`/queue` показывает первые 10 актуальных карточек. После обработки повтори команду; остальные записи также поступают уведомлениями. Старая карточка перестаёт действовать после её повторной выдачи. Если запись изменена или другой модератор уже принял решение, бот попросит обновить очередь и не перезапишет чужое решение. Сравнение версии выполняется внутри транзакции с блокировкой записи.

Результат и комментарий сохраняются в существующих полях модерации с ID модератора сайта. Принятие работы использует существующую логику публикации и уведомления подписчиков. История отправленных карточек и курсор входящих сообщений хранятся в PostgreSQL и сохраняются после перезапуска. При обрыве связи сразу после отправки возможна повторная карточка; это не позволяет повторно применить уже сохранённое решение.

Используется [long polling Telegram](https://core.telegram.org/bots/api#getupdates): бэкенд сам обращается к Telegram по HTTPS. Отдельный домен, webhook и входящий порт для бота не нужны. **Один токен должен использовать один запущенный экземпляр бэкенда.** В подготовленном PM2-конфиге уже установлен один экземпляр.

## 5. Бесплатное подключение из России

Сначала попробуй прямое подключение. Если оно работает, прокси не требуется. Если Telegram API блокируется, простой бесплатный вариант для твоего Windows-ПК — **Psiphon for Windows (Legacy)** с локальным HTTP-прокси. Он доступен бесплатно без аккаунта на [официальной странице загрузки](https://psiphon.ca/en/download.html).

1. Скачай Windows-клиент с официальной страницы. В свойствах exe проверь цифровую подпись **Psiphon Inc.**.
2. Выбери режим локального прокси, отключи режим VPN/L2TP. В настройках локальных портов задай свободный HTTP/HTTPS-порт, например `8080`. Если оставлен автоматический выбор, возьми фактический порт из интерфейса или журнала и подставь его в env.
3. Чтобы Psiphon не менял системный прокси Windows, останови подключение и установи `SkipProxySettings=1` в `HKEY_CURRENT_USER\Software\Psiphon3` через редактор реестра. Затем подключись снова. Это описано в [официальной справке Psiphon](https://psiphon.ca/en/faq.html).
4. Дождись подключения и укажи в приватном env бэкенда:

```dotenv
TELEGRAM_PROXY_URL='http://127.0.0.1:8080'
```

5. Проверь связь без токена бота:

```powershell
curl.exe --proxy http://127.0.0.1:8080 --head --max-time 30 https://api.telegram.org
```

Ответ HTTPS от Telegram подтверждает доступность API; строка `200 Connection established` сама по себе подтверждает только соединение с прокси. При ошибке подключения проверь фактический локальный порт и статус Psiphon. После изменения env перезапусти бэкенд и повтори привязку в настройках сайта: она дополнительно проверяет токен через `getMe`.

Прокси используется только клиентом Telegram. PostgreSQL, локальные переводы и входящие подключения к сайту сохраняют обычный маршрут. Полный VPN может менять маршрут ответов домашнего сервера и мешать пробросу портов. Локальный порт прокси не открывай на роутере и не делай доступным из интернета.

Psiphon должен оставаться запущенным. Для запуска после входа в Windows можно добавить его ярлык в автозагрузку; перед использованием бота проверь подключение. Бесплатное подключение зависит от провайдера и текущих блокировок, гарантий доступности нет. Windows-клиент помечен разработчиком как Legacy; при изменении его поддержки можно заменить его любым доступным доверенным HTTP/HTTPS CONNECT-прокси без изменения кода бота.

Эта настройка рассчитана на бэкенд, запущенный непосредственно в Windows. В Docker адрес `127.0.0.1` означает контейнер: он не сможет обратиться к Windows-прокси на loopback. Для Docker потребуется отдельный доступный контейнеру прокси; автоматического открытия Psiphon в домашнюю сеть здесь нет.

## 6. Перенос на другой ПК

```powershell
git clone https://github.com/Saven0k/ArtGallary.git
Set-Location ArtGallary
```

Затем выполни установку и сборку из [deploy/README.md](deploy/README.md), восстанови PostgreSQL и загрузки. Git содержит код и примеры конфигов, но не БД, картинки пользователей, токены и пароли. Приватный `.production.env` перенеси отдельно безопасным способом или заполни заново. После сборки выполни `telegram:migrate` с нужным `NODE_ENV`, включи бота и при необходимости настрой Psiphon.

Останови старый бэкенд с этим токеном перед запуском нового. При переносе полной БД привязки и курсор сохранятся; с новой БД сотрудники привязываются повторно. Если используется перевод, отдельно выполни шаги из [TRANSLATION.md](TRANSLATION.md).

## 7. Если не работает

- **«Бот пока не настроен»**: проверь `TELEGRAM_BOT_ENABLED='true'`, токен и выбранный env. Изменения env требуют перезапуска бэкенда.
- **«Нет соединения с Telegram»**: проверь токен, подключение Psiphon и HTTP-порт; SOCKS-порт нельзя подставлять вместо HTTP.
- **Ошибки таблиц**: выполни миграцию с тем же `NODE_ENV` и подключением PostgreSQL, что у работающего API.
- **Telegram API error 409**: обычно запущены два бэкенда с одним токеном либо для этого бота ранее настроен webhook. Оставь один экземпляр; существующий webhook нужно удалить через [метод deleteWebhook](https://core.telegram.org/bots/api#deletewebhook). Для нового бота он не нужен.
- **Telegram API error 429**: Telegram ограничил частоту; бот ждёт указанный Telegram интервал и пробует снова.
- **Бот заблокирован пользователем**: привязка автоматически удаляется после ошибки 403. Разблокируй бота и привяжи заново через сайт.
- **Нет карточек**: проверь наличие ещё не обработанных авторов или работ, привязку, права аккаунта и команду `/queue`.

Без токена живую отправку сообщений проверить нельзя. Автоматические тесты проверяют права, привязку, комментарии, подтверждение решений, конкурирующую модерацию, повторную доставку и ошибки транспорта.
